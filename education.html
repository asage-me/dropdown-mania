DD-001

The element you get for free

A native <select> is a complete dropdown: keyboard, screen readers, typeahead, mobile pickers, form value, no JavaScript. If this is enough, stop here.

Nothing chosen yet.

Practice

Give every control a real <label for>, keep an empty placeholder option when no default is honest, and never disable the placeholder — a disabled first option is how a select ends up submitted blank.

DD-002

The one you build yourself

A div-based dropdown buys you total styling and costs you every behaviour the browser was doing for free. This one is wired the way the ARIA select-only combobox pattern asks for: role="combobox", aria-expanded, aria-activedescendant.

Preservation method

  • Cold storage
  • Desiccation
  • Deacidification
  • Encapsulation in Mylar
  • Darkness and 18°C

Nothing chosen yet.

Practice

Keep focus on the trigger and move aria-activedescendant between options — moving DOM focus into the list is how custom dropdowns lose their scroll position. Support Enter, Space, Up, Down, Home, End, Escape, Tab and typeahead, or do not ship it.

DD-003

Anatomy

Five parts, and every dropdown in this archive has all of them, whatever it looks like.

Conservation grade
  • Archival
  • Museum board
  • Acid-free tissue
  1. 1Trigger — a real button, with a name that says what you are choosing.
  2. 2Current value — rendered inside the trigger, so the choice survives closing.
  3. 3Indicator — rotates on open; decorative, always aria-hidden.
  4. 4Listbox — one item is active (highlighted) and one is selected. They are not the same thing.
  5. 5Commit — Enter, Space or click writes the value and closes. Escape closes without writing.

Practice

Active is where the highlight is; selected is what will be submitted. Conflating them is the single most common bug in hand-built dropdowns — it makes Escape do nothing.

Multiple choice inside one dropdown. The discipline is showing what is selected while the menu is closed, and giving a way out of the pile.

Past a dozen options, scrolling is worse than typing. This is the editable combobox: the input is the trigger, so typing filters and Enter commits the highlighted row.

    Practice

    DD-007

    Grouped options

    Structure inside the list is information. <optgroup> is free, survives into the accessibility tree, and is the reason a 40-option select stays usable.

    Nothing chosen yet.

    Practice

    Group when the groups are real categories a reader would name. Alphabetising a flat list of 40 items is sorting; grouping it is thinking.

    DD-010

    Four ways to break one

    Each of these ships in production software every week. Try to operate them the way a keyboard or a screen reader would.

    Failure 1

    Hover-only

    • Annual
    • Quarterly
    • Condition

    This panel opens on hover and nothing else. Press Tab: it never opens. Touch users have no hover either.

    Failure 2

    No accessible name

    No label, no aria-label, no title. A screen reader announces only “combo box” and the current value — the purpose is gone.

    Failure 3

    Div with an onclick

    Choose a decade ▾

    Not focusable, no role, no options, no keyboard. It cannot be reached, so it does not exist for half your users.

    Failure 4

    Options that move

    A list that re-sorts while you are arrowing through it turns typeahead into a lottery. Freeze the order while the listbox is open.

    Practice

    The test costs ten seconds: unplug the mouse, or close your eyes and press Tab. If you cannot open it, choose one, and leave, it is broken.

    DD-011

    Choosing a pattern

    The honest table. Cost is what you have to build and test, not what you have to write.

    Dropdown patterns compared by cost, accessibility and when to use them
    PatternCostAccessible by defaultUse it when
    Native selectNoneYesOne value, list fits on a screen.
    Native + optgroupNoneYes10–40 values with real categories.
    input + datalistNoneMostlyValues are suggestions, free text is valid.
    Custom listboxHighOnly if you build itYou need rich rows, or styling the browser refuses.
    Multi-selectHighOnly if you build itFilters and tags — and you show the selection closed.
    ComboboxHighOnly if you build itMore than ~30 options, or remote data.
    Mega menuMediumOnly with click + EscNavigation for a large site, not a form value.

    Practice

    Reach for custom only when a native control has actually failed you, and write down which requirement it failed. “It looks better” is a real reason — it is just not a cheap one.
